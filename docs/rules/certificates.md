# Certificates and NOCs (Step 28)

- Change certificates only through `CertificatesService` (drafts, reads) and `CertificateActionsService` (issue, void, print, templates) in `src/certificates`; module `certificates`, area-scoped through the certificate's unit. Both write their own audit rows in the same transaction.
- A certificate is a draft until issued. Drafts change freely and may be deleted (`certificates.delete`); issuing (`certificates.approve`) is the only way out of a draft, and an issued one is only ever voided, once, with a reason (`certificates.approve`). Trigger `certificates_guard` enforces this; only the society cascade deletes an issued row.
- Issuing, in one transaction: the person is checked again (`CERTIFICATE_TIES`, and an active membership for a membership certificate), then the unit's unpaid bills (`unitDues`, via `duesDecision`): a no-dues certificate is refused while anything is owed (409 `certificate_dues_outstanding`), any other type needs `allowDues` (409 `certificate_dues_unpaid`), and the amount owed is recorded. Then the number (`NumberingService` kind `certificate`, `CRT-YY-NNNN` per fiscal year), the rendered `body`, the signer and the time are frozen. Never number a draft.
- Who may get which type is `CERTIFICATE_TIES` in shared; the person's current ties come from `unitTies` (`members/unit-ties.ts`), shared with vehicles.
- The letter text is the setting `certificate_templates` (`certificateTemplatesOf` over `DEFAULT_CERTIFICATE_TEMPLATES`), one Bangla and one English text per type, read with `certificates.view` and changed with `settings.edit`. Templates use only `CERTIFICATE_PLACEHOLDERS`; the society's name comes in through `{society}`, never from code. Changes apply to drafts and later issues; issued certificates keep their frozen `body`.
- A certificate is written and printed in its own `lang`, whatever the dashboard's locale: the print page renders `CertificateLetter` on the server with that language's `Certificates.letter` messages.
- Web: `/dashboard/certificates` (`src/lib/api/certificates.ts`, `components/certificates/`); the person picker uses `GET /certificates/unit-people`. `CertificatesPanel` sits on unit and person pages. Prints use the A4 named page.
- Not in v1 (decided 2026-10-24): fees, a public request form (`noc` stays in `UPCOMING_FORMS`), QR codes or a verification page.
